## Reading a project

Start with the question the project addresses, then follow the file map to its implementation or final report. Use the setup instructions in that project, since the collection spans Java, Python, browser applications, OpenGL, and CUDA.

Read a result alongside its evidence and validation scope. A saved training metric is different from a fresh benchmark, a file snapshot is different from a full upstream history, and a preserved paper does not imply that its original code or data is available. Each project's explanation records these distinctions where they apply.

## Continuing the collection

Update the relevant project first and record meaningful changes with current commits. Keep original submitted attachments identifiable, preserve team attribution, and refresh these indexes when a project is renamed or its verified state changes. The notebooks maintained in CIFAR-100 illustrate this approach: originals remain intact while working copies and targeted checks are developed separately.
